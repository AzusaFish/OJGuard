# OJGuard 演示脚本

建议时长：7～9 分钟。主线只演示一个 Java 运行时回归事故；节点退化和 Checker 缺陷在最后用证据摘要证明泛化能力。

## 演示前准备

1. 启动后端和前端，确认首页显示“服务正常”；
2. 如需展示真实 Java 对照实验，提前构建两个镜像并保留 `output/evidence/java-runtime-comparison.json`；
3. 关闭含个人信息的浏览器标签和通知；
4. 录制窗口只包含 OJGuard、必要终端和 AgentTeams 协作界面；
5. DeepSeek 只用于最后一次 AgentTeams 演练，不在反复录屏时重复调用。

## 0:00—0:40 问题与核心价值

画面：事故总览。

讲解：

“OJGuard 处理的是在线测评中会改变候选人成绩和晋级结果的批量事故。传统方式需要运维、题目、招聘和客服跨系统人工排查。OJGuard 把异常信号、根因实验、影响计算、审批、可信重评和结果验证收敛为一条可审计闭环。”

强调一句：

“Agent 负责理解和协作，确定性工具负责实验和计算，高风险动作由人审批。”

## 0:40—1:15 创建事故

画面：进入“事故列表”，选择“Java 运行时回归”。

讲解：

“场景固定种子生成 5000 名候选人和约 2 万条提交。Java 运行镜像变更后，TLE 明显升高，同时出现投诉；C++ 与 Python 基本不变。”

点击“创建并进入工作台”。

## 1:15—2:10 信号、假设与对照实验

画面：事故工作台的“信号与时间线”“根因与实验”。

讲解：

- 指标、部署和投诉被归一化为同一 Incident；
- “节点退化”和“运行时回归”作为竞争假设并存，时间相关性不会直接当成根因；
- 同一控制程序跨镜像、跨节点重放，由实验决定假设状态。

展示 `java-runtime-comparison.json`：相同代码、相同 80ms 时限下，正常镜像 3/3 为 OK，退化镜像 3/3 为 TLE。

## 2:10—2:50 影响范围

画面：“影响范围”。

讲解：

“系统只根据可观测字段计算影响集合，不读取模拟数据中的标准答案。主场景识别出 703 名候选人、742 条提交，并同时预估成绩和晋级变化。这个集合会固化到重评计划，后续批次不能越界。”

## 2:50—4:20 审批与分批重评

画面：顶部“下一步”操作区。

依次操作：

1. 技术审批：处置方案；
2. 技术审批：控制与灰度；
3. 执行控制组与灰度；
4. 业务审批：全量重评；
5. 执行全量重评。

讲解：

“我是单人参赛者，因此在同一操作者下切换技术审批和业务审批的角色上下文。系统完整记录角色、动作、理由和时间，用于验证职责分离，不表示真实多人签批。”

在“重评与成绩”展示四个批次：20 个控制提交、38 个灰度提交、500 和 184 个全量提交，全部完成且失败为 0。展示成绩、排名和晋级变化样例。

## 4:20—5:10 独立验证与关闭

画面：执行闭环验证，进入“闭环验证”。

讲解：

“关闭事故不只看服务恢复，还要独立检查所有批准提交是否覆盖、是否重复、是否越界，以及成绩和排名是否完成重算。”

展示：覆盖率 100%、重复 0、遗漏 0、越界 0、状态 RESOLVED。

完成业务审批并关闭事故，打开 HTML 事故报告。

## 5:10—6:30 AgentTeams 协作

画面：AgentTeams 协作记录或最终证据摘要。

讲解：

“Incident Manager 负责任务拆解和冲突裁决，六个 Worker 分别完成信号聚合、根因分析、影响计算、处置规划、重评执行和独立核验。每个 Worker 使用受限的 Skill 和 MCP 工具，不能绕过审批直接执行全量重评。”

必须展示：

- 六个 Worker 的结构化输出；
- 至少一次‘节点相关’与‘镜像相关’结论冲突；
- Incident Manager 要求执行二维对照实验，而不是投票；
- 工具调用与最终 Incident ID 能对应；
- 没有工具证据的模型结论只保留为假设。

## 6:30—7:15 泛化与收尾

画面：`scenario-summary.json` 或 PPT 的三场景对比。

讲解：

“同一状态机和重评引擎还验证了评测节点退化与 Checker 缺陷：前者影响 118 名选手、119 条提交；后者影响 71 名选手、73 条提交。三类场景重评覆盖率均为 100%，最终都通过独立验证。”

收尾：

“OJGuard 的卖点不是生成一份事故建议，而是把多 Agent 判断变成可执行、可审批、可验证、可审计的测评结果恢复流程。”

## 录制失败时的处理

- 前端数据未刷新：点击“刷新”，不要重复执行全量重评；批次使用幂等键，不会重复计算；
- Docker 实验不可用：展示已保存的 JSON 证据，并说明复现命令；
- AgentTeams 超时：停止继续调用模型，展示本次已生成的结构化任务和工具轨迹；
- 页面出现密钥、登录信息或个人通知：立即停止录制，清理后重新开始。
